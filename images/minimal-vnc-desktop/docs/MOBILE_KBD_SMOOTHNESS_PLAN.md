# Mobile keyboard/IME native-feel & 3G-smoothness — implementation plan

_Generated by the mobile-kbd-smoothness-audit workflow: 118 candidates proposed across 7 dimensions, 47 survived adversarial verification (real + not-already-done + stealth-safe). noVNC v1.6.0 source was read for the transport dimension._

## Verdict

The single biggest native-feel win is killing the multi-second "dead tap" on Android/EditContext: give it the optimistic in-gesture keyboard raise that iOS already has (handleTap L2316 currently gates on `isIOS` only), guarded by armDismiss + a grace-dismiss gate so a false hit self-corrects — that alone turns 3G keyboard latency from seconds to one frame for the overwhelmingly common "tap a known field" case. Cluster tightly around it a set of tiny, high-confidence correctness fixes that remove the least-native failures a user actually notices: silent CJK word loss on empty compositionend, cross-field text corruption on form auto-advance, "can't type a decimal" in type=number, "I closed the keyboard and it jumped back up," and the unbounded echo pill. These are almost all a few lines each, concentrated in kbd-autofocus.js, and most improve 3G typing feel directly. After that, coverage items (Android field prev/next, hardware-keyboard nav keys on the touch/EC paths, pattern/lang hints from the extension) close the platform holes, and a small number of deeper transport/quality changes (the Ctrl+V vs Extended-Clipboard race, bandwidth-adaptive JPEG quality, server-side move coalescing) harden the lossy link. Do NOT spend effort on the tempting transport tweaks (TCP_NODELAY, cross-event keystroke coalescing, H.264 preference, low-quality first-frame ramp) — each was verified to be a no-op or a regression on this specific TigerVNC/RFB stack.

## Quick wins (small, high-confidence correctness fixes)

### Deliberate dismiss beats a stale late confirm
**Impact:** Kills the 'I closed the keyboard and it jumped back up a second later' loop, which is worst on exactly the slow links where confirms arrive after the user has moved on.  
**Effort:** small — one line at two sites  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (dismissKeyboard ~L1240; onProxyBlur ~L595; recovery-raise gate L2757)`

In dismissKeyboard() and the onProxyBlur system-dismiss path set `lastTapAt = 0;` so the recovery-raise gate at L2757 (`... && lastTapAt && (nowMs()-lastTapAt) < ...`) can't re-pop the keyboard when a late editable:true confirm arrives. Prefer the unconditional clear over the candidate's `dismissedAt > 800ms` timestamp gate — on 3G the confirm routinely lands >800ms later, so a fixed gate still re-pops. Bonus: L2698 stops polluting emaLatency with an interrupted tap->confirm interval.

### Numeric / email / decimal field correctness
**Impact:** Fixes caret positioning (chew buffer, mirror seed, value-diff) on numeric/email fields and lets users actually type 1.50 into price/amount/quantity fields — a very common, currently-broken case.  
**Effort:** small — delete one block, change one map value  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (applyProxyImeHints L1077-1079 proxy.type block; inputmode map L1088)`

Stop assigning proxy.type from the remote type (delete the `allowed` set / keep proxy.type='text') and drive the keypad purely via the inputmode attribute; separately change the map entry `number:'numeric'` -> `number:'decimal'` at L1088. type=number/email break setSelectionRange (throws in fillIosBuf chew-buffer + seedProxyMirror) and type=number sanitizes the seeded value; 'numeric' is a digits-only pad with no decimal separator.

### Reset isComposing on blur / dismiss / raise
**Impact:** Stops an abandoned CJK/Korean composition (tap another field, back button, swipe-down mid-word) from wedging the next field's EC commit-only path and permanently latching eventComposing — a real corruption path amplified by the focus-flap churn lossy /kbd streams produce.  
**Effort:** small — 3 lines at 3 sites  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (onProxyBlur ~L595, dismissKeyboard ~L1240, raiseKeyboard)`

Add `isComposing = false; echoComposing = ''; ecSuppressed = false;` at all three sites (place unconditionally at the TOP of onProxyBlur). Drop composedSuppressed from the reset — it is dead code (never set true). Do NOT call resetEC() or write editCtx here; just clear the flags so the next field's first textupdate takes the normal (non-suppressed) branch.

### Recover committed IME text when compositionend.data is empty
**Impact:** Prevents a whole committed CJK/Japanese/Korean word from silently vanishing on older WebKit / some 3rd-party iOS keyboards / reconversion — a loss indistinguishable from packet loss on 3G. Also fixes a latent iOS autocorrect bug (trackIosWord was never called after a composed commit).  
**Effort:** small — one flag + rewrite one branch  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (onCompositionEnd L618-635)`

Add module-scope `composedForwarded`; set false in onCompositionStart, true after any sendText during composition (iOS beforeinput insertText/insertReplacementText). Rewrite L633: `if (e.data) { sendText(e.data); trackIosWord(e.data); } else if (!composedForwarded && proxy && proxy.value) { sendText(proxy.value); trackIosWord(proxy.value); }` then clear proxy + reset the flag. Do NOT use lastSentValue (unmaintained on iOS/desktop) and do NOT touch the EC path (it never reads .data).

### Tighten echo reconciliation (prefix-trim + RTT-scaled safety net)
**Impact:** Turns the echo pill from an unbounded wall of already-arrived text (only snapping empty on a pause) into an honest 'typing ahead of the pixels' indicator, and stops it clearing before its pixels land on multi-second links. Presents as a bugfix to a visible defect, not a new feature.  
**Effort:** small — restructure one branch + one expression  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (applySignal L2694-2695; reconcileEcho L830)`

At L2694 trim only the CONFIRMED leading chars (`confirmed = sync.len - baselineLen`, clamped [0, len]) from echoText instead of clearing all, so the pill tightens to just the in-flight tail. At L2695 replace the literal 8000 with `Math.min(15000, Math.max(8000, 4*linkLatency()))` — only GROW the window on slow links, never shrink it (today's 8s stays the floor). Keep the full-catch-up terminal case and retain the 8s net for when reconEnabled is false.

### Show local echo during the RFB reconnect gap
**Impact:** During a 3G blip + ~600ms reconnect the user keeps typing and sees characters accumulate instead of a dead field — the outage becomes invisible; the existing sync.len reconcile clears them after replay. Covers the exact window latency is worst.  
**Effort:** small — queued-branch calls + one replay guard  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (sendText L115, sendSpecialKey L141, flushSendQueue L71-82, renderEcho L787)`

Call echoAppend(text) / echoBackspace(count) on the rfb-down queued branch before the early return. Add a `replayingQueue` guard set true around flushSendQueue's loop and gate the real-path echoAppend(L133)/echoBackspace(L149) on `!replayingQueue` so replay doesn't double-echo. In renderEcho, bypass the ECHO_MIN_RTT_MS floor while `rfbReady===false` (a disconnect is by definition high-latency).

### Fix Indic ZWJ backspace over-deletion
**Impact:** Removes silent residual-character corruption when deleting joined Devanagari/Tamil/Bengali/Malayalam conjuncts (Marathi eyelash-ra, deliberate ZWJ), which the current EMOJIISH-includes-ZWJ heuristic under-counts. Silent and unrecoverable when hit.  
**Effort:** small — rewrite one function in keys.js  
**Files:** `images/minimal-vnc-desktop/kbd/keys.js (backspaceCountFor L44, EMOJIISH regex)`

Segment always and count per grapheme cluster, collapsing to 1 only when a cluster carries a true pictographic/regional-indicator scalar (EMOJI_SCALAR = /[\u{1f000}-\u{1ffff}\u{1f1e6}-\u{1f1ff}\u{2600}-\u{27bf}\u{2b00}-\u{2bff}]/u), else add cluster.length. Non-emoji clusters (all Indic incl. ZWJ conjuncts) sum back to deleted.length exactly. Keep the graphemeSeg==null fallback = deleted.length.

### Collapse newlines when pasting into a single-line field
**Impact:** Stops a pasted trailing newline (copy a line, paste ~10 chars into a search/login box) from firing Enter and instantly submitting/navigating — a jarring, non-native failure on 3G where each stray Enter round-trips. Only the <=32-char / non-extended-clipboard sendText path is affected today, which covers the common case.  
**Effort:** small — one guarded line  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (insertPastedText ~L711)`

At the top of insertPastedText: `if (currentHints && currentHints.tag === 'INPUT') text = text.replace(/[\r\n]+/g,'');` (positive INPUT test — the viewer has no contenteditable flag; TEXTAREA/contenteditable report other tags). Strip (matches HTML one-line value sanitization) rather than replace-with-space. Edit only insertPastedText (the single choke point for all three paste entries); don't collapse when currentHints is null.

### Arm the stuck-keyboard watchdog on every keyboardActive=true site
**Impact:** Closes the wedge window where a keyboard raised purely by a geometry detector has no watchdog — if a later /kbd dismiss frame is lost (common on lossy links) and the proxy loses focus, nothing forces the clean dismiss. Bonus: auto-cleans a spurious raise from an iOS URL-bar collapse.  
**Effort:** small — 2 lines  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (handleViewportResize ~L1712; VK geometrychange h>0 ~L1808)`

Add `startWatchdog();` after the `keyboardActive = true;` in those two detector-driven raise sites (raiseKeyboard/noteProxyInput/handleLayoutResize already arm it). Do the two-liner, NOT a setKbdActive() refactor (the helper would need threading through 7 true-flip sites and the watchdog already self-stops when keyboardActive is false).

### Future-proof iOS/iPadOS IME-path selection
**Impact:** Prevents a future WebKit build that exposes window.EditContext from silently flipping every iOS device onto the never-exercised EC path (breaking accessory bar, mirror, QuickType-off, chew-buffer), and keeps iPadOS on the correct WebKit path if navigator.platform gets masked. Pure insurance, zero present-day behavior change.  
**Effort:** small — 2 expressions + a warn line  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (ecMode assignment in setup, ~L2962; diagnostic ~L2939); images/minimal-vnc-desktop/kbd/env.js (isIOS L11)`

Set `ecMode = !DESKTOP && !isIOS && typeof window.EditContext === 'function';` and update the ec= diagnostic to match; add a one-time dbg warning when the latent condition (`isIOS && EditContext present`) is detected so the team knows the day WebKit ships it. In env.js broaden the iPad branch to `(/Macintosh|Mac OS X/i.test(ua) && maxTouchPoints>1)` (subsumes the deprecated navigator.platform==='MacIntel' read, can't match real Macs or desktop Chrome).

## Medium-term (coverage + platform holes)

### Optimistic tap-raise on Android / EditContext
**Impact:** THE marquee 3G win: perceived keyboard latency on Android/EC drops from a full tunnel round-trip (1-3s+) to one frame for the common 'tap a known input rect' case, matching iOS. False hits (icon over a text field) self-correct via armDismiss.  
**Effort:** medium — 3-line core but the grace guard is load-bearing and needs on-device 3G testing  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (handleTap hit branch L2316-2320; grace-dismiss branch L2786-2801)`

Extend the iOS-only optimistic block to `if (isIOS || isAndroid || ecMode) { const wasActive = keyboardActive; raiseKeyboard('tap-hit'); if (!wasActive && !STATELESS) armDismiss(); }`. REQUIRED companion (or it regresses on 3G): gate the L2788 grace-dismiss so it can't tear down an optimistically-opened keyboard before the confirm/recovery window — while a recent tap is still awaiting its first editable:true and !remoteFocusKey, let armDismiss own teardown instead of the 350ms fixed grace. clearDismiss() at L2679 already cancels the armed timer on confirm; the L2757 `!keyboardActive` guard prevents double-raise.

### Clean slate on remote-driven field switch
**Impact:** Fixes silent text corruption on multi-field forms (OTP auto-advance, checkout tab-through, JS focus()) where A->B emits editable:true(B) with no intervening false, so the value-diff / mirror path diffs B's first edit against A's leftover buffer -> spurious backspaces / duplicated text. Confined to the value-diff <input> fallback + iOS mirror, but a real correctness bug there.  
**Effort:** small-medium — merges field-switch-reset + mirror-reseed into one isNewField edit  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (applySignal isNewField block L2696; seed branch ~L2714)`

In the isNewField block while keyboardActive: if mirrorOn() set `mirrorNeedsSeed = true;` BEFORE the L2714 seed block (so field B reseeds from its real sync.val); else `if (!isComposing) clearProxy();` (resets proxy.value/EC buffer AND lastSentValue). Optionally reset iosWord too. Guard: only clear when (lastSentValue||proxy.value) non-empty.

### Recalibrate layout-resize baseline on orientation / posture change
**Impact:** Fixes keyboard mis-detection on Firefox Android / adjustResize WebViews after rotate-into-landscape (baseline only ratchets UP today, so a shrunk landscape height reads as 'keyboard up') and foldable/split-view resize while typing — the exact browsers with no VK API fallback.  
**Effort:** small-medium — one listener + one guarded branch (merges two candidates)  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (dedicated orientationchange listener; handleLayoutResize L1765/1787)`

Add a dedicated `orientationchange` listener (NOT the startMagnify one at L3164 — that only runs in MAGNIFY): after a ~400ms settle, `if (!keyboardActive && !keyboardOpening && document.activeElement !== proxy) baselineInnerHeight = window.innerHeight;`. Also at the top of handleLayoutResize track lastInnerWidth and re-baseline + skip the shrink/grow decision when `Math.abs(innerWidth-lastInnerWidth) > 100` (foldable unfold / split-view resize).

### Don't let stale rects turn a post-scroll tap into a dismiss
**Impact:** Prevents 'scrolled the remote page, tapped a visible field, keyboard vanished' — rects are in remote-doc coords and lag scroll by the 250ms/1500ms extension report + tunnel RTT (wide on 3G). Auto-clears the instant any post-scroll rect report lands, so genuine off-field taps still dismiss promptly.  
**Effort:** small-medium — one timestamp + one guarded condition (magnify-only, acceptable)  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (queueMove/onTouchMove; hitTest/handleTap L2281/2323)`

Stamp lastRemoteScrollAt in queueMove when TOUCH_INPUT && remoteTouchActive (forwarded remote scroll; local pan is excluded). Inside hitTest, downgrade 'miss'->'unknown' while `lastNonEmptyRectsAt < lastRemoteScrollAt` AND `nowMs()-lastRemoteScrollAt < DISMISS_MAX_MS` (5s cap). Do the downgrade BEFORE lastTapWasMiss is set so the L2760 suppression uses the downgraded value.

### Native Enter-key behavior (derive label + honor next/previous)
**Impact:** The return-key glyph reads correctly (Search/Go) and actually advances fields on multi-field forms where the label already says 'next' but currently fires Enter (misleading + premature submit). Reduces taps on Android forms with no accessory bar.  
**Effort:** medium — 6 call sites, mechanical, but easy to miss the beforeinput pair  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (applyProxyImeHints L1099; 6 action-key sites: beforeinput L348-350 & L390-392, onProxyKeyDown L561/577/589, onECKeyDown L1048)`

In applyProxyImeHints derive `enterkeyhint` from type when the remote didn't set one (search->'search', url/email->'go'). Add a sendActionKey() helper reading currentHints.enterKeyHint: 'next'->sendSpecialKey('Tab'); 'previous'->sendShiftTab(); else Enter. Replace all SIX action-key sites (the two beforeinput insertLineBreak paths are the primary Android/iOS single-line path — omitting them silently no-ops the feature).

### Android field prev/next affordance (accessory-bar parity)
**Impact:** Gives Android (Gboard/EC has no accessory bar) the same one-tap field advance iOS gets — today Android forces dismiss + tap-an-occluded-field on every multi-field login/signup/checkout. Stealth-safe (reuses existing remote Tab).  
**Effort:** medium — new buttons + guard wiring + positioning  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (makeMagnifyButton; onMagButton L1537; updateControlButtons; navRemoteField L686)`

On isTouch && !isIOS && !DESKTOP add two floating chevrons wired to navRemoteField(-1/+1) (remote Shift+Tab/Tab). Position on the LEFT edge (paste stays right) using the same visualViewport inset; add them to onMagButton() so the magnify touch guards don't swallow the tap; drive visibility via updateControlButtons and SHOW when keyboardActive. Optional: gate on rects.length>=2.

### Forward hardware-keyboard nav / shortcut keys on the touch + EC paths
**Impact:** Makes a tablet-with-keyboard feel native — caret nav, Shift+arrow selection, Ctrl+A/C/X/Z reach the remote instead of being swallowed. Covers iPad+Magic/Smart Keyboard, Android tablets + BT keyboard, Samsung DeX. Pure keysym forwarding (already batched, stealth-coherent with a Windows touch+BT-keyboard persona).  
**Effort:** medium — one helper, two call sites, test JP/CN candidate-window arrows + AltGr still work  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (onECKeyDown ~L1047, onProxyKeyDown ~L555; reuse DESKTOP_KEYSYMS/sendKeyChord/desktopKeysymFor)`

Add ONE shared helper called after the composition guard in both onECKeyDown and onProxyKeyDown: if `e.code && e.key!=='Unidentified'` and DESKTOP_KEYSYMS[key] exists (arrows/Home/End/Delete/PageUp-Down/F-keys) -> preventDefault + sendKeyChord; if (ctrlKey||metaKey) && single-char && key!=='v' -> sendKeyChord(desktopKeysymFor(e)). The `e.code && !Unidentified` gate is the soft-keyboard firewall (Gboard glide / iOS soft keys fire Unidentified / keyCode 229).

### GPU layer + motion-adaptive JPEG quality during forwarded scroll/drag
**Impact:** On a thin 3G uplink frame SIZE (not RTT) gates scroll fluidity; halving JPEG bytes during forwarded scroll lets 2-4x more frames through (slideshow -> continuous), full quality returns on settle. will-change guarantees the composited fast path so pinch/pan track fingers on low-end phones.  
**Effort:** medium — reuse existing quality machinery + centralized will-change owner; ownership discipline is load-bearing  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (onTouchStart remote-forward branch ~L2019/2035, onTouchEnd; beginPinch/beginPan for will-change; reuse savedQuality L2361-2391)`

Add lowerMotionQuality()/restoreMotionQuality() (qualityLevel ~2-3) gated on linkLatency()>=TYPING_QUALITY_RTT_MS, hooked ONLY on the remoteTouchActive forwarded-drag branch (NOT client pinch/pan — those are pure CSS transforms with no remote frames). Debounce-restore ~300ms after motion; restoreMotionQuality must bail if keyboardActive (typing owns savedQuality) — use a single owner tag. Separately set `will-change:transform` on #screen at beginPinch/beginPan/snap start and clear it via one debounced timer ~200ms after the last transform (drop translateZ — composeScreenTransform rebuilds the transform string every frame).

### Server: advise viewers when the last publisher (extension) disconnects
**Impact:** Closes the 'keyboard wedged up after the remote extension MV3 worker died with editable:true cached' case for ALREADY-connected viewers (the publishers>0 resync gating only protects NEW viewers). The publisher link is loopback, so publishers==0 reliably means the worker died, never a network blip -> 4s debounce is safe.  
**Effort:** small — ~15 lines of Go, no client change  
**Files:** `images/minimal-vnc-desktop/proxy/keyboard.go (remove L104/109; publish; lastState L32/128)`

In remove(), when publishers==0, `time.AfterFunc(~4s)` re-checks publishers==0 under mu and, ONLY if cached lastState currently parses as editable:true, fans out a canned {editable:false} via publish(nil, ...). Concurrent timers from a publisher flap are harmless (idempotent, re-check under mu). Do NOT clear lastState. No client change needed — applySignal already grace-dismisses on editable:false.

### Richer field hints: pattern-numeric + lang/dir + OTP QuickType
**Impact:** Numeric pad appears on the legacy pattern="[0-9]*" OTP/PIN/zip idiom (currently full text keyboard); Arabic/Hebrew get correct RTL direction + language dictionary; iOS one-tap SMS OTP autofill works. pattern/lang/dir are public attributes so no content leak on sensitive fields.  
**Effort:** medium — spans extension + viewer; regex must be strict  
**Files:** `images/minimal-vnc-desktop/extensions/proxy/content.js (describe() hints L259-271); images/minimal-vnc-desktop/kbd-autofocus.js (applyProxyImeHints L1087/1135)`

content.js: publish `pattern: attr('pattern')`, `maxLength: (isInput && el.maxLength>0)?el.maxLength:undefined`, `lang` (nearest [lang] or document lang) and `dir` (nearest [dir]/document.dir). Viewer: when no inputmode/type-numeric, derive inputmode='numeric' from a STRICT digits-only pattern (`^(\[0-9\]|\\d)([*+]|\{\d+(,\d*)?\})?$` after stripping anchors — matches [0-9]*/\d{6}, rejects separators/alternation). Set proxy.lang/dir (and propagate dir to the mirror bar + echo pill so RTL renders). Exempt one-time-code from the L1135 QuickType force-off + set autocapitalize='none' so the SMS code chip shows on type=text OTP fields. Do NOT wire maxLength to the live proxy (would truncate the chew buffer).

### Focus-lifecycle hygiene bundle
**Impact:** Removes a family of low-frequency-but-annoying focus glitches: ~2s stale-keyboard lag returning from background, unrepro keyboard drop while rapidly paste+tab+dismiss, cross-field text leak on reconnect (search text into a now-focused password field), post-reconnect flicker, and phantom rects across remote navigation.  
**Effort:** medium — five ~2-line edits across client + extension  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (visibilitychange/pageshow L3123; allowBlur sites navRemoteField/pasteFromDevice/dismissKeyboard; enqueueSend L66/flushSendQueue L77; detach full path L3228); images/minimal-vnc-desktop/extensions/proxy/content.js (pagehide)`

Five small independent hardenings: (1) On visibilitychange->visible, after a 300ms settle, dismiss-only if keyboardActive && !keyboardOpening && !keyboardJustDismissed && activeElement!==proxy (drop the re-raise branch — iOS won't raise without a gesture). (2) Replace the shared allowBlur boolean with a monotonic deadline `allowBlurUntil = Math.max(allowBlurUntil, Date.now()+N)` (onProxyBlur checks Date.now()<allowBlurUntil) — latest window wins, no pairing/leak. (3) Tag each enqueued item with remoteFocusKey; in flushSendQueue skip (drop, don't re-target) items whose fk != current remoteFocusKey. (4) detach() full path: `clearDismiss(); clearFalseDismiss();` + reuse the canonical L2791-2799 field-gone reset (remoteFocusKey=null, reconFieldKey=null, etc.) + lastSentValue=''. (5) content.js: on pagehide (IS_TOP only) emit {editable:false, rects:[], ...} so the hub caches a clean state across remote nav.

## Deeper changes (transport / quality hardening)

### Fix Ctrl+V racing the Extended-Clipboard Provide handshake on paste
**Impact:** Fixes a guaranteed wrong/empty paste of long text (CJK block, passphrase, multi-line note) on exactly the slow mobile links this project targets — silent corruption of a pasted passphrase is nasty when it hits.  
**Effort:** medium — touches noVNC privates (already-flagged fragile); needs 3G on-device test with CJK + ASCII passphrase  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (insertPastedText L711-723, remoteCtrlV L661); vendored noVNC core/rfb.js privates (rfb._sock, RFB.messages.clientCutText / extendedClipboardProvide)`

On the extended-clipboard path clipboardPasteFrom only sends Notify; the real transfer is the async Notify->Request->Provide handshake, but remoteCtrlV() fires synchronously so Ctrl+V reaches Xvnc before the server clipboard holds the text (empty/stale paste on high-RTT). Split: (a) Latin-1 text -> RFB.messages.clientCutText directly + immediate remoteCtrlV (single ordered message, zero race); (b) non-Latin -> one-shot wrap RFB.messages.extendedClipboardProvide so remoteCtrlV fires only after the Provide frame is queued (stream ordering guarantees server processes it before the following KeyEvents); (c) fallback timer ~3*linkLatency()+1000ms + dbg; clear the one-shot on dismiss/blur; keep the per-char sendText try/catch fallback. NOTE the race fires for ALL >32-char pastes once the server negotiates extended clipboard (TigerVNC does), not just non-Latin.

### Bandwidth-estimate adaptive JPEG quality
**Impact:** Targets the true bottleneck for full-page frame smoothness (bandwidth, not RTT). On a genuinely narrow pipe it trades invisible quality for frame rate; on a fat pipe it keeps text crisp — self-tuning across the huge variance of mobile links instead of one static 5/9 operating point.  
**Effort:** medium — burst-gated sampler + hysteresis on noVNC privates; confound-avoidance is the hard part  
**Files:** `images/minimal-vnc-desktop/kbd-autofocus.js (attach; observe rfb._sock inbound bytes; new pickQualityForBandwidth + periodic tick; unify with lowerTypingQuality owner)`

Sample inbound bytes/sec into a bwEMA and pick qualityLevel from measured kbps with hysteresis. CRITICAL: passive bytes/sec is NOT clean capacity — when Continuous Updates isn't engaged, arrival is RTT-gated, and idle windows read ~0. So sample ONLY during saturating multi-frame FBU bursts (>~30KB/1s), require N consecutive same-band samples, adjust DOWN aggressively / UP slowly / never on a stale reading. Adapt qualityLevel only (compressionLevel=9 is CPU not bytes). Guard on rfb._sock/_recvMessage shape and degrade to static 5/9 + RTT-only typing drop if internals change. Route through a single quality owner (max-restrictive wins) so motion/typing/bandwidth don't fight.

### Server-side touchMove coalescer (stuck-finger / HOL hardening)
**Impact:** Makes touch smoothness robust regardless of client behavior and defends the touchEnd path from being head-of-line-blocked by stale moves in the multi-client (inputMaxClients=8) / congested-CDP cases — closing a documented server gap. Sell as stuck-finger hardening, not a 3G smoothness win (the client throttle already bounds the normal path).  
**Effort:** medium — ~25-35 lines Go, but the ordering discipline is load-bearing and MUST ship with the interleave test  
**Files:** `images/minimal-vnc-desktop/proxy/emulate.go (dispatchTouch; session() select loop; setActive/detach)`

Add `pendingMove` slot + mutex keyed to the active sessionId. For touchMove store params under the mutex INSTEAD of queue(); for start/end/cancel keep queueImportant AND clear the slot under the same mutex BEFORE enqueuing (clear-before-enqueue guarantees no stale move after lift). ### Proxy transport hygiene bundle (writev frame coalescing + bounded readFrame alloc)
**Impact:** (1) Trims the lone header-only TCP segment per frame (~4% fewer segments on 32KB pixel chunks, more on small frames) — modest fewer packets/radio wakeups on 3G. (2) Hardens the unauthenticated mobile-facing control channels against a single malformed frame forcing a large up-front allocation before the 8192 cap is applied. Both low-impact security/efficiency hygiene.  
**Effort:** small-medium — two contained changes, but sequence the drain-on-reject carefully to avoid stream desync  
**Files:** `images/minimal-vnc-desktop/proxy/main.go (writeFrameToConn L959-966; readFrame L969+); images/minimal-vnc-desktop/proxy/keyboard.go (readLoop L252)`

(1) In writeFrameToConn use `net.Buffers{header, payload}` and its WriteTo (single writev syscall on *net.TCPConn, zero payload copy, transparent fallback if wrapped) instead of two conn.Write calls or a concatenating copy — same for the masked client->upstream direction. (2) Add readFrameCapped(r, max) wrapping readFrame internals that rejects at the length header by draining the declared bytes via io.CopyN(io.Discard,...) (preserves stream framing + the current tolerant 'ignore oversized frame' semantics); call it with 8192 on /kbd and /input, keep the 64MB ceiling on /websockify (legitimate large clipboard Provide blobs). Leave readFrame as a thin wrapper so the ~14 other call sites + tests are untouched.

## IME / platform coverage gaps (most-likely-missed first)

- type=number amount/price/quantity fields: 'numeric' inputmode has no decimal separator (can't type 1.50) AND proxy.type=number sanitizes the seeded value + breaks setSelectionRange (chew buffer / mirror seed) — very common, broken today
- Legacy numeric/OTP/PIN/zip fields using pattern="[0-9]*" or \d* with no type/inputmode (the pre-inputmode iOS idiom): get the full text keyboard instead of a numeric pad — pattern hint is not published
- Android multi-field forms (login/signup/checkout): no field-to-field prev/next (Gboard/EC has no accessory bar), forcing dismiss + tap-an-occluded-field
- CJK / Samsung / Chinese IMEs switching fields mid-composition on a lossy link: isComposing never resets without compositionend, wedging the next field's input
- Older WebKit / some 3rd-party iOS keyboards / Japanese-Korean reconversion firing compositionend with empty data: the committed word is silently dropped
- Indic scripts using explicit ZWJ conjuncts (Marathi eyelash-ra, deliberate Devanagari/Tamil/Bengali/Malayalam joiners): backspace under-counts, leaving residual characters on delete
- Tablets/phones with a hardware/Bluetooth keyboard that keep pointer:coarse (iPad + Magic/Smart Keyboard, Android tablet + BT keyboard, Samsung DeX without a mouse): arrows, Shift+arrow selection, Home/End, Delete, PageUp/Down and Ctrl/Cmd chords are silently swallowed on the EC and iOS/Android <input> paths
- Arabic / Hebrew and other RTL fields: no lang/dir hint forwarded, so writing direction and language-specific dictionary/autocorrect are wrong
- iOS autocomplete=one-time-code text fields: QuickType is force-disabled for all iOS fields, suppressing the SMS AutoFill code chip users most want
- Foldables mid-fold (Fold/Flip/Pixel Fold) and Firefox-Android / adjustResize WebViews rotating into landscape while typing: layout-resize baseline only ratchets up, wedging keyboard detection on the browsers with no VK API fallback
- Future iOS/iPadOS WebKit build that ships window.EditContext: every iOS device silently flips to the never-exercised EditContext path (breaking accessory bar, mirror, QuickType-off, chew-buffer) with zero code change
- iPadOS if navigator.platform stops reporting 'MacIntel' (privacy build / UA reduction): the iPad falls out of isIOS and loses the accessory bar, temp-readonly raise gesture, and mirror mode

## Do NOT do these (verified no-op or regression on this TigerVNC/RFB stack)

- **Set TCP_NODELAY on the /websockify bridge and hijacked/upstream VNC sockets** — Go's net package already enables TCP_NODELAY=true on every TCPConn (setDefaultSockopts on both Dial and accept/hijack), so Nagle is already off on both ends. The ~40ms hold this targets does not exist; the call is a no-op, and the `if _, ok := conn.(*net.TCPConn)` guard would silently skip on any wrapper anyway.
- **Coalesce keystrokes across separate input events into one WS frame on a timer** — Human inter-key gaps (~150ms even at 80wpm) far exceed any sane 20-40ms window, so the timer fires between keystrokes and merges nothing. The large edits worth coalescing (glide word, paste, autocorrect delete+retype) are each ALREADY a single input event -> single sendBatched -> single frame. Net gain is marginal while it adds fragile timer lifecycle across reconnect/dismiss/blur.
- **Proactively pull an incremental framebuffer update after a keystroke burst** — In request-driven mode noVNC re-sends a full-framebuffer incremental request after EVERY FramebufferUpdate, and TigerVNC parks it until pixels change — so a keystroke is answered off the standing request immediately, no extra RTT. And TigerVNC supports Continuous Updates, which noVNC auto-latches, so the request-driven path isn't even in effect. An extra request just duplicates the standing one (redundant re-encode).
- **Prefer/force H.264 (WebCodecs) or otherwise pick the pixel encoding** — Pixels come from stock TigerVNC Xvnc, which has no server-side H.264 encoder — it only emits Tight/ZRLE/JPEG. Encoding is server-chosen, so H.264 rects never arrive no matter what the viewer advertises (noVNC already lists H.264 first). Only the logging sliver is non-done, and that is diagnostics, not a smoothness win.
- **Render the local echo AT the field's on-screen rect instead of a centered pill** — reconcileEcho only fires on remote catch-up or the 8s net, so real repainted pixels can land before the overlay clears — an in-place overlay would then sit ON TOP of freshly-rendered glyphs with mismatched font metrics (visible duplicate/flicker); the centered pill deliberately hides exactly this. Also: tiny illegible font on zoomed/fit pages, and caret/pre-content misalignment on populated/mid-field-edited fields.
- **Promote ?mirror=1 to the iOS default, or extend the WYSIWYG bar to the Android EditContext path** — The value-diff engine is end-anchored ('remote caret is at the end of oldV'); seeding the full field and letting the user tap into the MIDDLE to fix a typo makes the diff backspace the tail at the remote's END caret -> silent corruption. That is why mirror is kept an iOS-only experiment. Separately, EditContext is headless — the browser paints nothing into the div — so a bar there displays nothing without a whole manual render+caret+characterBounds pipeline, and seeding a non-empty EC buffer breaks the commit-only/empty-buffer-backspace invariants.
- **Fire a haptic pulse when a keystroke round-trips** — The 'sent' moment is local-instant (sendText writes the queue synchronously) and fires at the same instant the OS soft keyboard already delivers its own press haptic — pure redundancy. The only informative 'landed' pulse arrives 1-3s later via reconcileEcho and reads as random noise, not acknowledgment. Marginal-to-negative UX for annoyance + battery cost.
- **Local CSS-transform scroll echo / inertial momentum to mask drag RTT** — At zoom=1 (the only regime where a one-finger drag forwards as a remote scroll) magnify mode reflows the remote to the viewport and shows it 1:1, so #screen holds ONLY the visible pixels — translating it reveals a blank/stale gutter, not the next content (unlike echoed keystrokes, the incoming pixels aren't known to the viewer). There is also no scroll-offset feedback signal anywhere to reconcile against, so the real frame snaps to a disagreeing offset (nested scrollers, momentum, clamping) — a jarring double-jump, plausibly worse than honest freeze-then-catch-up.
- **Connect at low quality for a fast rough first frame, then ramp up** — noVNC's qualityLevel setter only resends SetEncodings — it never requests a full non-incremental frame, so a static page stays blurry until a SECOND full frame is forced (more bytes on the thin pipe). And the text/web-UI first frames here are dominated by lossless Tight (governed by compressionLevel, already max 9), which quality barely shrinks. Also collides with the typing-quality owner and the fit-dance is already masked by the opaque cover.
- **Re-emulate at higher framebuffer density (deviceScaleFactor>1) when zoomed in and settled** — Pixels are a fixed-geometry Xvnc X11 framebuffer, not a device-pixel screencast. The devs verified in-code that CDP deviceScaleFactor does NOT change the raster into the VNC framebuffer — DSF only changes reported DPR and crops/rescales, so DSF>1 gives the same artifact as DSF<1. Real density needs growing the Xvnc framebuffer + reflowing the page (a jarring relayout) and ~zoom² more bytes — strictly worse on 3G.
- **Route the keystroke uplink on its own connection** — Keysyms ride the RFB socket (rfb._sock) by design — the 'keyboard via RFB only' constraint. Splitting the uplink needs either a proxy-side RFB injector that writes KeyEvent frames into the upstream (a major build) or CDP (a forbidden automation signal). TCP send/recv directions are already independent, so downlink pixel bufferbloat doesn't block the tiny keysym uplink — near-zero real payoff for large effort + constraint tension.
- **Make the RFB reconnect delay RTT-adaptive instead of fixed 600ms** — There is no stampede — the reconnect setTimeout only re-arms inside the disconnect handler after the prior attempt fully resolves, so retries serialize as (failure time ~seconds) + 600ms. rttEMA rides the SAME tunnel, so it's stale/0 during an outage and collapses max(600, rttEMA) to 600 exactly when it would 'help'; when non-zero it only adds black-screen latency. A transient 3G drop doesn't fire the 'online' event either.
- **Model mid-field re-composition / arrow-key caret repositioning in the diff** — Because the remote field has no IME and the client only appends/backspaces its tail, the remote caret is invariantly at end and remote==lastSentValue, so the end-anchored diff already yields the correct final string wherever the LOCAL caret is (it only costs a larger tail rewrite, an efficiency cost). On 3G commitOnly withholds all intermediate churn anyway. Arrow-keysym caret repositioning would break the caret-at-end invariant every IME path relies on and permanently desync remote caret vs lastSentValue on length-changing edits.
- **permessage-deflate for /kbd, shorten WS keepalives, or tune TCP for carrier-NAT idle timeouts** — Both channels already keep both directions warm — /websockify's 25s server ping elicits the browser's automatic pong, and /kbd's 5s client ping is echoed. permessage-deflate is already declined in the hand-rolled 101 handshake (no Sec-WebSocket-Extensions echoed, no RSV1 path). And RFC 5382 mandates multi-minute TCP NAT timeouts, so 25/30s already sits well inside any real window; shorter pings just add 3G radio wakeups for nothing.
- **Debounce /emulate + resize on orientation change / viewport churn** — Already implemented in startMagnify: onResize sets resizeSession=false during the burst, clears/resets a 350ms pushTimer and commits the final size once via settle()->pushEmulate(); orientationchange defers 400ms; keyboardActive returns early; pushEmulate dedupes on lastEmulateKey; enterFit/exitFit own resize with their own phase timers + ping-pong latch. Every viewport-derived path already coalesces to one final size.
